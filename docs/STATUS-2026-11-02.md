# dsh-mobile-app 现状与下一轮计划（2026-11-02）

> 这份文档是本轮「独立复核 → 逐项决策 → 实现 → 真机验证」的落点。
> `docs/BACKLOG.md` 是候选池，`docs/backlog_gemini_reviewd.md` 是 Gemini（第 1-12 节）
> 与 Codex（第 13 节）两份评审材料——**三份都不是批准的实施计划**。

## 0. 一句话

本轮把「审批拍板」和「连接真实性」两项做成了**可验证的真机行为**（不是只跑单测），
并把当时凭代码分析判定为「暂时验不了」的三项，用一个可切换模式的假网关补齐了实测数据。

## 1. 本轮的做事方式

1. **独立复核**：不预设 Gemini / Codex 任意一方正确，逐条回到代码与协议核对，
   区分「源码确认 / 可能但未复现 / 产品假设 / 未验证」。
2. **逐项决策**：把第 5 节列出的 10 个问题交给用户逐条确认，用户全部认可后才动手。
3. **实现 + 真机验证**：每个结论都要有真机/真网关数据支撑；造条件的工具留在
   `.scratch/`，可复跑。

### 2.3 仍有争议 / 证据不足

- 同会话并发多条同类型审批的实际频率：协议支持，宿主是否并发 ask 未复现。
- 首页语音「A 的回答发给 B」的时序窗口：代码路径成立（转写期间 A 被处理、B 变成唯一待办），
  真实时序未复现。
- 12s / 5s / 1.5s 这三个时限：属于**候选值**，本轮已按候选值实现并实测，但它们不是
  「最优值」，需要更多网络样本再调。
- iOS 音频会话是否真被占：只在 Android 上验过。

### 3.1 第一项：审批目标绑定 + 命令可见 + 会话隔离

做了什么：

- **绑定**：首页语音不再发 `approval-response`。会话有任意待办时，语音只负责把用户带到
  现场并聚焦审批卡（`App.tsx:620-646`）；control 未就绪时也不把「同意」当普通消息发进去。
- **看见**：折叠坞显示 shell 真实命令；`approvalRisk(approval, command)`（`risk.ts:41`）
  把命令纳入判定；补 PowerShell/Windows 规则；`toolCommand` 支持 `bash/sh/pwsh/powershell/exec`。
- **拦住**：shell 类审批拿不到命令时，折叠坞与展开卡都禁止一键批准；目录信任也不会自动放行
  （`SessionScreen.tsx:1927-1928`）。
- **不猜**：`callId` 缺失时不再猜「最后一条工具」，改为显示「无法定位」。
- **队列**：审批改 FIFO（`interactions.ts` 的 `enqueueApproval/removeApproval`），
  折叠坞显示「还有 N 条」；失败/失效可见（`accepted:false` 复位 busy，`not-pending` 移除并提示）。
- **隔离**：`SessionScreen` 按 `sessionId` 重挂载（`App.tsx:1331`），引用/目录信任/待发回显/
  语音请求/滚动锚点随会话结束；悔棋窗在切会话、进后台、卸载时立即提交
  （`SessionScreen.tsx:1167-1184`）；「快照」文案删除。

真机验证（真审批：`pwsh` 申请 `danger-full-access` 删除 `C:\Users\example\dsh-approval-test`）：

- 折叠坞显示 `高危命令: pwsh`、真实命令 `Remove-Item -LiteralPath '…' -Recurse -Force`、风险标签「递归删除」。
- 用户实测：按住约 0.3s 松开，水位填充回退，**没有误批准**。
- 点「× 拦截」后探针收到 `approval-resolved outcome=rejected`；测试目录与 `victim.txt` 未被删除；
  agent 正常解释并结束回合；App 无卡死/白屏。

### 3.2 第二项：连接真实性

做了什么（`src/transport/gateway-client.ts` + 新增 `src/transport/connection-policy.ts`）：

- 握手截止：从创建 socket 起 12s 内没有 `hello`/`paired` 就断开重连；只有收到 `hello` 才清退避。
- 旧 socket 守卫：`onopen/onmessage/onerror/onclose` 全部校验 `socket === this.socket`。
- 探活：回前台/切网恢复后发 ping，5s 内没有任何帧就主动断开重连。
- 网络切换：第一次网络回调只建基线，**之后任何 online 事件**都当作一次网络切换（1.5s 防抖）。
- 4003/4004：停止自动重连，并区分「设备被撤销」和「重新开启鉴权」；App 提示改为引导重新配对。
- `send()` 对 socket 在检查与发送之间关闭的情况做 try/catch；重连定时器不再叠加。
- 删掉 App 层重复的「回前台就 connectWith」effect，统一由客户端探活负责。

真机验证（真机 4238a31c / 真网关 yong_huang / 假网关 3999）：

| 场景 | 实测 |
|---|---|
| 冷启动 | 2 个连接（主 + control），「已连接」 |
| 后台 35s 回前台 | 仍是 2 个连接，未等 50-75s |
| 撤销设备（4003） | clients 2 → 0，10s 内无重连；提示「设备授权已被撤销，请重新配对」 |
| **12s 握手截止** | open→close **12.001~12.015s**；重连间隔 1.026s / 2.016s / 5.014s；App 显示「连接超时，正在重连」 |
| **5s 半开探活** | 回前台 → **5.118s** 主动断开 → **1.009s** 后重连 |
| **WiFi 关** | **+2.313s** 发出探活 ping → **+5.008s** 断开 → **+1.02s** 重连 |
| **WiFi 开** | 关联完成后 +2.67s 探活 → **+5.005s** 断开 → **+1.005s** 重连 |

**测试逼出来的真实缺陷**：`expo-network` 的 `type` 在 WiFi↔5G 时不可靠（WiFi 断开后
type 仍是 WIFI），只按 offline→online 或 type 变化都会漏掉切换——这就是 `602426c` 的由来。

## 6. 验证方法与可复用工具

### 6.1 假网关（本轮新写，`docs/tools/fake-gateway.mjs`）

端口 3999，三种模式，HTTP 控制面：

```
node docs/tools/fake-gateway.mjs                    # 起服务
curl "http://127.0.0.1:3999/mode?value=no-hello" # no-hello | half-open | normal
curl "http://127.0.0.1:3999/log"                 # 连接/关闭/ping 时间线
curl "http://127.0.0.1:3999/pair?host=usb"       # 生成假网关配对二维码（usb | lan）
```

- `no-hello`：只发 `paired` 不发 `hello` → 造「TCP 已连但握手不完成」。
- `half-open`：发 `hello` 之后不回 ping → 造半开连接。
- `normal`：正常回 pong / sessions。
- `paired` 只在首连（带配对码）时发，否则 App 的 `paired` 分支会重启 control，造出假 churn。

### 6.2 真机命令


## 7. 未验证与限制

- 没有在 iOS 上验过（音频会话、返回手势）。
- 12s / 5s / 1.5s 是候选值，只在一台设备、一套网络下测过。
- 假网关不实现真实会话协议，只能验连接层，不能替代真网关的业务链路。
- 没有做真机掉帧测量，所以没有对渲染性能下结论。
- 本轮只改了 App 与假网关脚本，**没有动网关协议**，也不需要网关配合。

## 8. 下一步（建议顺序）

1. **第三项：语音健壮性**——还剩三块：按住后立刻松手的启动竞态（现在会把录音状态卡死）、
   用 `speech-catalog` 的 `maxDurationSeconds/maxAudioBytes` 做上限与倒计时、
   语音失败统一提示。**需要你定**：到点自动停后是「直接发出」还是「把文字放回输入框让你改」。
   **还需要你点头**：本机网关语音 `available=false`，真机验转写得上有语音模型的那台主机。
2. **第四项：发件箱回执关联**——`sent/error` 按 requestId 归位 + `gatewayId` 隔离；
   注意网关对普通消息不去重，只能做「已发送 / 未确认」，不能自动重发。
3. **第五项：历史 L1 内存缓存**——第一项已把会话生命周期理顺，现在加内存层最省事。
4. **FLOW-1 胶囊折叠**——用户早就反馈过，需要一起看改完的效果。
5. **小项**：Android 返回键、下载 open/read 超时、ErrorBoundary/帧分发 try-catch、原子写落盘。
