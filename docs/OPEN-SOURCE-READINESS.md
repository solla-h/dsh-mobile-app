# 发布与验证状态

DSH Mobile 当前是 **Android public alpha**。下载入口是
[GitHub Releases](https://github.com/solla-h/dsh-mobile-app/releases)。
支持的宿主与插件组合以 [`compatibility.json`](../compatibility.json) 和
[兼容记录](COMPATIBILITY.md) 为准。

## 已发布版本

[`v0.1.0-alpha.5`](https://github.com/solla-h/dsh-mobile-app/releases/tag/v0.1.0-alpha.5)
是当前版本，提供签名 APK、`SHA256SUMS` 和 `build-info.json`。它由[发布流水线](https://github.com/solla-h/dsh-mobile-app/actions/workflows/android-release.yml)
构建：原生构建、签名、签名产物的完整模拟器旅程、附件上传，随后对发布产物独立下载校验文件哈希、APK 密码学签名、
包名与版本；任一环节失败都不会发布。Android versionCode 为 5，包含 arm64-v8a、armeabi-v7a、x86 和 x86_64。
本版本尚未做实体设备复验，其真机结论待补；下方 `alpha.4` 的真机记录属于更早构建。

`alpha.4` 曾在 `alpha.3` 之后修复阻止私有网络 `ws://` 连接的 Android 配置。已检查下载 APK 的 Manifest，
并由 Android 模拟器通过实际原生 WebSocket 完成旅程；客户端仍拒绝公网明文网关地址。
上述私有网络 `ws://` 策略结论属于源码/产物/模拟器确认；下文的真机旅程使用既有配对，
不据此声称所有网关地址类型都已在实体设备上验证。

官方 APK 使用 GitHub Ubuntu runner、Expo prebuild 和 Gradle 构建，不使用 EAS 云构建配额。
发布 tag 必须来自已合入 `master` 的提交，已发布 tag 和附件不替换。操作流程见[发布手册](RELEASING.md)。

## 证据边界与待验证项

- **源码/测试确认：** 上述单元与 UI 集成测试；Android 14 模拟器中，编译后的测试 APK 完成了本地合成网关旅程，

- **真机实测：** 较早的 Android 16 preview 构建验证过配对、会话列表、文字回复和按住说话，
  具体组合见兼容记录。2026-11-07 又对官方 `alpha.4` 完成下述实体 Android 16 旅程；两份证据分别归属各自构建。

  单手操作体验。200% 字号只通过基础收发，仍有显示裁切；固定几何的转盘文字也有局部字号上限。

### alpha.4 实体设备复测（2026-11-07）

使用 GitHub Release 的原始签名 APK（versionCode 4，源码 `c7acacb`），在 Android 16 / API 36
手机上覆盖安装既有 versionCode 1，未卸载、清除数据或重新配对。测试使用单独的合成会话和文本附件。
真实宿主在该会话中的只读自检回报 DSH `0.2.1-rc.5`、网关 `0.12.0-rdv.3` 及固定 GitHub 来源；
这不是重新部署或独立检查运行进程的证明。

| 用户路径 | 真机观察与边界 |
| --- | --- |
| 覆盖安装 → 打开原会话 | 已保存的网关、历史和精确草稿保留；新版成功收到真实宿主的文字回复 |
| 会话 → 后台约 115 秒 → 回前台 | 会话和草稿保留，随后仍能收到宿主回复 |
| Wi-Fi → 移动网络 | 切换后继续收发；此项不作为完全离线证据 |
| 关闭 Wi-Fi 和移动数据 → 发送两条 → 强制关闭/重开 → 恢复网络 | 两条均明确显示“待发送”，重启后按先后顺序得到两条回复；另一次完全离线冷启动显示缓存会话列表，没有回到配对页 |
| 按住麦克风 → 上滑 → 松开 | 录音和“松手取消”状态可见，取消后未产生新回合；不等同于转写与语音回复通过 |
| 附件入口 → 相机/相册/文件选择器 → 取消 | 均回到原会话，草稿保留；相机只验证打开和取消，没有拍摄个人场景 |
| 200% 字号 → 会话 → 文字收发 | 成功收到实际回复；回答卡片右上角的“主视窗聚焦”装饰标签被裁切，不能标为完整适配 |
| TalkBack → 聚焦附件入口 → 双击 | 实际打开附件菜单；完整遍历、返回和播报质量未完成验收 |

本轮还发现以下限制，不能用自动化绿灯掩盖：

- **文件发送未通过：** 一次选择合成附件并发送文字后，宿主回复称未收到附件；复测时，系统文件选择器
  返回后的附件状态明确显示“连接已断开”。源码确认只发送已取得 receipt 的文件，而文字发送成功会清空
  整个附件列表，包括失败项；选择器返回时的连接恢复时序仍需进一步定位。
- **发送触摸仍待定位：** 键盘打开时多次点击发送键中心未入队，改点左侧成功；收起键盘后也成功。
  测试期间有系统通知/来电浮层，因此尚不能把原因归结为右侧转盘。离线队列持久化和补发通过，
  不代表所有点击位置都已验证通过。
- **语音转写未通过验收：** 电脑播放固定合成语音、手机按住录音的尝试没有取得有效转写证据；
  同期宿主显示模型请求 `RATE_LIMIT`，但不能据此断言它就是转写失败原因。

测试后恢复原字号、无障碍和联网设置。公开记录不包含私人会话、网关地址、设备标识或来电/通知截图；
ADB 操作与屏幕观察也不代替真人对拇指动线、播报清晰度和操作负担的评价。

### 附件恢复修复（真机复验通过，已随 `alpha.5` 发布）

针对上述真机发现，源码已调整文件上传恢复：选择器返回时若连接未就绪，保留已选文件并等待重连；
重连后重新上传，上传失败可原地重试或移除。只要仍有未上传成功的文件，文字和语音发送路径都不会
略过它们并清空附件。移除、离开会话或旧连接的迟到回包不能恢复已取消的上传。

新增 App 旅程回归覆盖失败→重试→发送→返回、选择器期间断线→等待→重连、已上传文件再次断线、
等待期间移除与退出；上传层回归覆盖迟到校验/回包与取消。回答卡片标题允许换行，修复大字号标签溢出。
本次源码的全量检查通过：36 个 Jest suites / 349 个测试、37 个 Node 脚本测试、typecheck、lint 和文档相对链接检查。
其中额外覆盖原连接仍可写时的暂时错误：探活恢复不会作废附件收据或重复上传，在该状态下新进入会话也能上传。

2026-11-08 在实体 Android 16 设备上复验。复验使用本地构建的验证包：原生文件与 `alpha.4` 一致，仅替换为
当前源码编译的 Hermes JS bundle，签名证书与 `alpha.4` 相同，versionCode 仍为 4，APK SHA256
`7ed0f5ce21fb8a0b1246348b04a0cb74212d7d27437f71e3d209952b8f0b55d9`；以覆盖安装置于既有 `alpha.4`
之上，未卸载、清除数据或重新配对，已保存的网关、会话、历史与字号设置保留。

| 用户路径 | 真机观察 |
| --- | --- |
| 新建会话 → 附件入口 → 文件 → 选择器返回时断开 Wi-Fi 与移动数据 | 附件条显示“等待连接后上传”，发送键禁用，已输入草稿保留，会话未退回配对页 |
| 恢复网络 | 自动重连并自动重新上传，附件条显示文件大小，发送键恢复可用 |
| 发送（键盘打开、点击发送键中心） | 消息入队；宿主出现一次 `Read` 工具调用，并以合成附件中的标记行原文回复，附件未被丢弃 |
| 200% 字号 → 打开该会话 | 回答卡片标题换行，装饰标签“主视窗聚焦”完整显示，不再被裁切 |
| 返回并重新启动 App | 会话、历史与设置保留，网关重新连接 |

边界：本轮未能针对真实宿主制造上传失败，失败→原地重试与移除的交互仅由上述 App 旅程回归覆盖，
未在设备上走通；“发送键中心/左侧”的触摸现象本轮点击中心成功一次，仍不足以推翻此前未定位的结论。
上述为本地验证包结论，未生成或发布该验证包对应的 APK。修复本身已包含在 `alpha.5` 的发布中
（见 [CHANGELOG](../CHANGELOG.md)），但那次真机复验用的是本地构建、versionCode 仍为 4 的验证包，
不是 `alpha.5` 产物；`alpha.5` 尚未在实体设备上复验，`alpha.4` 及其失败记录保持不变。

完整验收应从打开 App 开始，覆盖成功、失败、取消、返回、后台恢复和重新打开；记录心流中断、
拇指动线与操作复杂度，见[开发与验证](DEVELOPMENT.md)。未附真实测试证据的能力不标记完成。
