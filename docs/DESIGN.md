# 设计原则

DSH Mobile 面向离开桌面时的三个动作：查看进度、处理待办、继续对话。Agent 在用户自己的 DSH
宿主上执行；手机负责呈现状态、收集输入和传达明确的决定。

## 使用体验

- 首页优先呈现需要用户处理的事项和当前会话；常用操作靠近单手拇指可达区域。
- 采用克制的纸张色调与信息层次。状态变化应可读、可追溯，减少无关动效和重复提示。
- 用户正在阅读旧消息时保持其位置；只有用户选择跟随时才持续滚动。
- 离线和重连应保留会话、草稿和上下文。发送、接收确认、失败和待重试状态不能混为一谈。
- 有风险的审批必须让用户明确决定，不能为减少操作步骤而自动批准或隐藏权限范围。

## 无障碍

- 主要操作提供名称、角色和必要的状态；图标与长按手势需要可访问的操作方式。
- 正常文字与背景保持足够对比度，状态不能只依赖颜色。
- 尊重系统字号，通过换行、最小高度和滚动布局容纳文字，紧凑排版不优先于可读性。
- 自动化检查、模拟器验证和真机屏幕阅读器测试分别记录，不能相互冒充。

## 实现约束

- 沿用现有状态驱动的导航，保持连接与会话状态一致；不增加第二套路由状态。
- 协议映射保持为可测试的纯函数。传输、存储和视图各自承担清晰职责。
- 提取模块是为了集中行为和减少理解成本，不以减少入口文件行数为唯一目标。
- 复用已有抽象，新增状态、后台行为或跨层依赖时说明必要性与失败后的恢复路径。
- 每项变更按完整用户旅程验收：如何进入、正常/失败/取消、继续操作、返回和重新打开。

这些原则用于评估当前改动，不是功能排期或未验证能力的承诺。
