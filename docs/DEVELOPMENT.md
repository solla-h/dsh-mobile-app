# Development and validation

This guide is for app contributors. For gateway installation, use [AGENT-SETUP.md](AGENT-SETUP.md),
[COMPATIBILITY.md](COMPATIBILITY.md), and the [user guide](USER-GUIDE.md).

## Local development

Use Node.js 22.13+ and npm:

```bash
npm ci
npm start
npm test -- --runInBand
npm run test:node
npm run typecheck
npm run lint
npx expo-doctor
```

Run Jest, typecheck, and lint for code changes. Also run `expo-doctor` after changing dependencies
or app config. Documentation changes need a relative-link check.

Use `npx expo install <package>` for native dependencies. `android/` and `ios/` are generated by
Expo prebuild: configure native behavior in `app.json` and config plugins, not generated files.
Read the [Expo 58](https://docs.expo.dev/versions/v58.0.0/) and
[React Native 0.88](https://reactnative.dev/docs/0.88/) documentation before changing native behavior.

## Where changes belong

| Module | Responsibility |
| --- | --- |
| `App.tsx` | Gateway and connection lifecycle, navigation state, global pending work and session coordination |
| `src/ui/home/AllSessionsView.tsx` | Controlled list, workspace groups, search and session actions |
| `src/ui/home/PairingViews.tsx` | Pairing form and add-gateway modal |
| `src/ui/home/RenameSessionModal.tsx` | Rename form |
| `src/ui/SessionScreen.tsx` | Active conversation, composer, history and session actions |
| `src/protocol/` | Pure frame mapping and validation |
| `src/transport/` | WebSocket, transfers, reconnect and offline outbox |
| `src/storage/` | Gateway identity, drafts, history and session caches |

The app uses one state-driven navigator. Search, collapsed groups, drafts and selected session
remain owned by the coordinator so changing tabs or connection state does not reset them. Keep
callback identities stable. A disconnected active session stays mounted; a paired user keeps the
cached list. See [AGENTS.md](../AGENTS.md) for protocol and lifecycle invariants.

## Automated user journeys

Jest imports the real `App` and `SessionScreen`, replacing the native adapters and gateway transport:

```bash
npx jest src/ui/__tests__/app-journey --runInBand
```

The journeys cover:

- Invalid pairing → valid pairing → all sessions → conversation → send and receive → return.
- Paired cold start with a cached list and failed connection → enter conversation → edit draft →
  another disconnect preserves the conversation and draft.

These are UI integration tests. They do not prove native networking, camera, audio or device gestures.
Pure protocol, transport and theme-contrast tests run in the same Jest suite.

The [Android check workflow](../.github/workflows/android-check.yml) builds a self-contained test APK
for relevant pull requests. The reusable [Android journey workflow](../.github/workflows/android-journey.yml)
installs it in an Android emulator and runs [Maestro](../.maestro/android-journey.yaml): pair with a
local fixture, open a session, send text, receive the fixture reply, return and relaunch with pairing retained.
The driver also checks gateway traffic so an optimistic local echo cannot count as a received reply.

The release pipeline runs that journey against its signed APK before publishing. PR test APKs use
only generated development signing and are temporary CI artifacts, not official downloads.
Screenshots, test reports and diagnostics use synthetic fixture data. Check the workflow result;
adding a workflow is not evidence that it has passed. The workflow does not need production tokens,
Cloudflare access, an Expo token or a physical phone.

## Fake gateway

```bash
node docs/tools/fake-gateway.mjs
adb reverse tcp:3999 tcp:3999
```

Open `http://127.0.0.1:3999/pair?host=usb` on the development computer to obtain the fake pairing code.
For a phone on the same LAN, start with `LAN_HOST=<your-lan-ip>` and use `/pair?host=lan`.
The fixture's `/pair.json` endpoint supports automation without a browser.

Use deterministic failure modes instead of waiting for an unreliable real network:

```bash
curl "http://127.0.0.1:3999/mode?value=no-ack"
# Restore normal replies when finished:
curl "http://127.0.0.1:3999/mode?value=normal"
```

Modes include `normal`, `no-ack`, `reject`, `no-hello`, `half-open`, `no-history`, and `no-create`.
See the [fixture header](tools/fake-gateway.mjs) for their behavior. It has fake credentials and test
control endpoints; use it only on a trusted local development network. Stop your fixture process
when finished.

## Real-device journey

Record the build/commit, OS, initial state, network path and outcome. Never record real pairing
payloads, hostnames, account IDs, device identifiers or credentials in public evidence.

1. Open the app from a cold start, both unpaired and already paired.
2. Pair or load the cached list; check invalid input, retry, cancel and leaving midway.
3. Enter a session, read history, send text, receive a reply and edit a draft.
4. Disconnect and reconnect; check that history, draft and reading position remain usable.
5. Exercise changed actions, including attachment cancellation and voice permission/cancellation
   when those paths are in scope. Use the pinned backend in `compatibility.json`.
6. Return to the list, background/foreground the app, then quit and reopen.
7. With TalkBack and large system text, repeat the route. Check action names, focus order, custom
   session actions, clipping and the return path.

Record interruptions, thumb travel and operation count, including failures and cancellation.
A CI emulator run does not replace physical microphone/camera, screen-reader or one-hand checks.
For real approval probes, use a disposable test workspace and reject or withdraw by default;
never auto-approve a dangerous action merely to complete a test.

## Android debugging notes

- `adb reverse` mappings are lost when the adb server restarts. Restore port 8081 for Metro or
  the fixture port as needed. Confirm the foreground app before injecting any gesture.
- If changed code appears stale, check `curl http://127.0.0.1:8081/status` and Metro logs. A failed
  bundler can leave the device displaying an older bundle.
- Use ASCII for `adb shell input text`; Chinese input is not reliably supported. Do not change
  the device's enabled keyboard list for automation.
- A single injected tap is not proof of an interaction. Inspect the resulting UI and protocol
  traffic. Map coordinates using the original screenshot dimensions, not its resized preview.
- Git Bash may rewrite `/sdcard/...` arguments. For file transfer, use
  `MSYS_NO_PATHCONV=1 adb pull /sdcard/capture.mp4 <local-path>`.
- For brief animations, record video and extract every frame with
  `ffmpeg -i capture.mp4 -fps_mode passthrough frames/%04d.png`. Use frame timestamps and recorded
  gateway events for timing, not the minute-only status-bar clock.
- Delete captures that include unrelated private content. Publish only reviewed synthetic examples.

## Interaction constraints

Use one animation driver consistently for a transform. In modals, attach gesture responders to the
actual hit-test view and preserve child buttons and scrolling. Do not add decorative animation state
that can conflict with an in-progress gesture.

Do not use `scrollToEnd` for chat pinning. Use `scrollToOffset` with the height measured during that
layout pass, follow only while pinned, and preserve reading position when the user scrolls up.
On `turn/end` while pinned, anchor the last user message to the first visible row.

Plugin management uses the control connection and correlates by `requestId`. `pendingBuilds` require
an explicit decision. Disabling the gateway itself requires a warning and reconnect confirmation.
Voice readiness comes from `speech-catalog.providers[].preparation.phase`, not the provider root.

## Evidence levels

- **Source/test confirmed:** inspected implementation and runnable automated checks.
- **Real-device observed:** an actual physical-device journey with a stated build and environment.
- **Still a hypothesis:** plausible behavior without reproduction.

Identify emulator observations explicitly within automated test evidence. Keep limitations visible;
never promote a previous build's results into verification of a new APK.
