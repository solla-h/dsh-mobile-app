# 路线图与候选池

> 性质：**候选池与决策台账，不是排期，也不是功能承诺。** 每一项都按[设计原则](DESIGN.md)单独讨论后再决定
> 做 / 不做 / 什么时候做 / 用什么最小方案做。
>
> 口径：本文件整理 2026-10/11 开发期间记录的能力候选（首页 v6.1/v6.2 计划、产品 UI 候选池、地址簿设计与研究笔记、
> 真机验证记录），并在 2026-11-10 逐项对照源码核对过状态。分级：
> **源码确认**（当前 `src/` 有实现或确无实现）、**仅文档记录**（设计稿提过、从未进入代码）、
> **已决策不做**（写明理由与再考虑条件）。
> 原始讨论、状态日记、私有主机记录与过期设计稿按仓库约定不入库；本文件只保留能力、状态与决定。
>
> 关联：[协议覆盖](protocol-coverage.md)、[地址簿工程参考](rendezvous-design.md)、
> [发布与验证状态](OPEN-SOURCE-READINESS.md)、[兼容记录](COMPATIBILITY.md)、[开发与验证](DEVELOPMENT.md)。

状态词表：`待讨论` → `做` → `部分做` / `已做`；`不做` 必须写明理由和再考虑触发条件。
已做与不做的条目**保留在下方对应小节**，不静默删除——这是本文件与状态日记的区别。

## 1. 未完成（用户可见）

| 能力 | 现状 | 最小方案 | 触发条件 / 备注 |
| --- | --- | --- | --- |
| 服务端全文搜索（SEARCH-1） | `search` 帧解析与单测已在 `src/protocol/search.ts`，列表搜索仍是本地标题/目录过滤，没有发送点 | 提交时发 `search`，命中先打开会话，再做消息定位 | 先确认 pin 的网关是否回显 `requestId`；命中只有 `sessionId`+`snippet`、单次 20 条、无翻页、可能落在归档会话 |
| 本地通知（NOTIFY-1） | 未安装 `expo-notifications`；审批、提问、回合结束都没有通知 | 仅 `AppState !== 'active'` 时发本地通知，点击回会话 | JS 被挂起或进程被杀后不可达，不要承诺「后台一定收到」 |
| 子会话寻址（TEAM-1） | 无 `subagentMode`，`history`/`subscribe`/`message` 只带 `sessionId` | 独立子会话 target 注册表 + 能力位门控 | 确认存在 agent-team 使用场景再做；完整团队面板见 §5 |
| 目录绝对路径与盘符（DIR-1） | `DirectoryPicker` 只有面包屑和子目录列表；Windows 多盘宿主新建项目看不到非系统盘 | 顶部加「跳转路径」输入与盘符快捷行，错误沿用 `directory-unreadable` | 只在 Windows 多盘宿主机场景有感 |
| 工作区文件浏览（FILE-1） | `file-list` 只有请求类型，无响应映射、发送点与界面 | 补响应映射 + 只读浏览；预览继续用系统能力 | 预览已由系统覆盖，缺的是浏览器 |
| 平板 / 大屏断点（PLAT-1） | `app.json` 锁 portrait，单栏状态机，无宽度断点与正文 `maxWidth` | 先做宽度断点与最大内容宽度，双栏后置 | 有平板 / 分屏用户再做 |
| 会话控制保真（CTRL-1） | 全局默认模型只有类型无发送点；`command-selected` 只用 label；`commands` 的 locale 固定中文 | 默认模型读写 + 二次确认；command 回退 `selected.id`；locale 跟随系统 | 多数是小口子，可单项做 |
| 置顶会话 | `pinnedSessionIds` 已解析进项目模型，但列表不排序、无标记、无置顶操作 | 列表排序 + 标记 + 行长按置顶 | 依赖置顶集合的推送帧缺失，变化只能重查 |
| 定时任务账本 | 列表有 cron / 状态 / 最近结果，详情可改名、删除、看投递历史 | 补「最近几次结果」汇总与「立即跑一次」 | 定时任务页当前是只读视图为主 |

## 3. 工程质量与健壮性

优先「先测量再调」，没有真机测量不下结论。

| 项 | 现状 | 说明 |
| --- | --- | --- |
| 流式渲染节流（PERF-1） | 每个 text/thinking delta 都直接进 state 并触发全量重组 | 约 100ms 合并 + 流式期间纯文本降级 |
| 长会话窗口（PERF-2） | 消息只增不裁；主列表未设窗口参数 | 条数或字节上限，裁剪与缓存策略一起定 |
| 单帧上限与背压（PERF-3） | `onmessage` 同步解析后逐个分发，无单帧上限 | 大帧日志 + 上限 + state 前瘦身 |
| 下载超时（MISC-3） | `file-resolve` 有超时，`file-download-open/read` 没有 | 服务端不回帧时卡片会一直停在 downloading |
| 审批通道断线标记（MISC-4） | control 断线时待办仍按旧数据渲染 | 标明「通道重连中 / 可能过期」，不要直接清空 |
| 存储管理（MISC-5） | 只有会话列表缓存与 L1 历史 | 做了磁盘历史缓存之后才需要 |

另：Android 新架构下 `LayoutAnimation` 默认不生效，`ThinkPill` / `ActivityGroup` / `ToolGroup` / `TrajectoryView`
的折叠仍是瞬跳；会话落地行已改为手写 `Animated` 淡入，其余按使用反馈再排。

## 4. 地址簿 v2+ 硬化

v1（当前实现）已覆盖「网关换址免重扫」这一主要需求；以下是纵深防御与边界收紧，未做不影响当前用户旅程，
按威胁模型与真实反馈决定是否投入。细节见[地址簿工程参考](rendezvous-design.md)。

- 网关身份钉扎（配对载荷携带公钥、连接前校验），以及与之配套的 `hello` 地址同步、挑战-应答证明；
- 候选地址 failover：`endpoints` 已存储并在刷新时整表替换，但重连只用其一，首项失效不尝试其余；
- Worker 侧：记录 TTL / 孤儿清理、请求限流、持久清理队列与写 fencing；
- 客户端网络层：禁止重定向、限制接收字节；
- 长期 key 的主动轮换入口（目前只被动采纳网关下发的新 key）；
- 局域网扫段重发现（当前只把已知地址写进加密记录）。

## 5. 已决策不做

| 项 | 理由 | 再考虑条件 |
| --- | --- | --- |
| 语音直接代批高危 | 首页拿不到 `callId` 与参数，盲批不可逆 | 网关把参数放进审批帧 |
| 提问（question）队列 | 当前只有一个提问槽位（源码里是单个 `question` state）；审批有 FIFO，提问没有 | 真实并发被复现 |
| 底栏 Tab 收敛 | 与首页规范一致；减少 Tab 并不改变底栏高度 | 不做 |
| 语音新建零延迟跃迁 | 需要乐观切入语义，现有反馈已够 | 用户反馈等待感明显 |
| 聚焦卡实时动作 | 首页拿不到实时工具流 | 网关推送推进事件 |
| 交付物内联预览 | 系统预览 / 分享已覆盖 | 用户反馈预览不便 |
| 表格全屏 / CSV、JSON 格式化查看 | 收益窄，只在读大表格、genui 输出时有感 | 出现真实抱怨 |
| 上下文用量环 | 现有水位线与统计已够 | 用户要看明细 |
| 团队 / 子代理面板 | 协议面大、依赖宿主实验插件、暂无用户 | 有 agent-team 用户 |
| 后台常驻 / 实时活动 | Expo 无等价 API；需原生模块与 dev build | 需要强提醒 |
| SQLite 历史、嵌入式 PDF / 高亮库、照搬其它架构、视觉模仿 | 体量与收益不划算，见候选池原始记录 | 场景变化 |
| 发件箱自动重发 | 网关对普通消息不去重，自动重发会产生重复 | 网关支持去重 |
| 官方共享地址簿实例 | 只支持用户自持 Worker（隐私与运营成本） | 不做 |
| 内建检修 Agent（REPAIR-1） | 运行形态、授权模型、降级路径均未定；**用户明确先不做** | 需要「不在电脑边也能检修宿主」时再评估 |
