## 3. 详述

### 3.1 FLOW-4 返回键

会话页返回→列表（不再退 App）；列表页返回→退桌面（`topResumedActivity=com.miui.home`）；
Modal（轮次 outline）开着→先关面板、仍留会话页。键盘开着时第一下返回是关键盘、第二下才回列表——系统行为，非问题。

### 3.2 第四项 #4：两条路径，一条挖出规格缝隙

**A. 连着发（socket 活着）+ 网关不回执/不回显 → 卡死**（真机实测 + 源码确认，假网关 `no-ack` 造的条件）：
气泡「发送中…」+ 头部 THINKING 持续 6 分钟以上；「停止」因网关无 `session-cancel` 应答而 40s 超时回退；
返回列表无待发徽标（phantom 不在发件箱）；重进会话痕迹全丢（消息实际已进网关）。
源码定位：connected 发送走内存 `pendingSends` 乐观回显与乐观 `running`，两者都**没有超时收尾**
（`UNCONFIRMED_AFTER_MS` 只作用于发件箱条目）。与假网关注释/场景文档的「20s 后标未确认」预期不符 ⇒ **规格缝隙**。
爆炸半径较小：真实网关正常路径必回 `sent` + echo + turn 事件，此状态需要「TCP 活着但网关对该消息完全静默」。

**B. 设计内路径全链路 PASS**：真断线（停网关）→ 发「待发送 · 联网后自动重发」→ 重连 ready 自动 flush（新 requestId）
→ 20s 翻「未确认 · 可能没送达 + 重试/移除」→ 中途退列表「全部会话」tab 有「待发送 1」徽标、状态不丢
→ `mode=normal` 点重试（**新 requestId** `70b10d11` ≠ 原 `0ec4e0cc`）→ `sent` 回执、条目删除、变正常气泡。
注意语义：「未确认」措辞正确——消息可能已送达（回执丢了），重试=可能重复送达（网关不去重，与 OUTBOX-1 决策一致）。

### 3.5 FLOW-1 ③ 收拢动画：30fps 录屏逐帧判定

快速模型让整个回合 ~2 秒跑完，1 帧/秒连拍抓不到动效；改用
`adb shell screenrecord`（VFR，活跃段源帧实测 ~110fps）+ `ffmpeg -fps_mode passthrough` 全帧抽取 + 逐帧差分。

判定（两个独立样本一致）：
1. **无淡入淡出**：「展开行删掉→胶囊出现」在两源帧间（≤7.9ms）完成整定；终态胶囊 4x 放大后文本锐利、
   满不透明度、无鬼影。设计预期（`ActivityGroup.tsx:42`：240ms create/delete opacity）未呈现。
2. **无视口跳动（关键）**：切换前后 diff bbox 仅限该行区域，消息气泡等锚点像素完全不动——
   痛点 3 的「尺寸跳变引发视口跳」已消除；丢的只是柔和观感。
3. 机制（**仍是假设**）：`configureNext` 在组件挂载后的 useEffect 里调用，挂载提交已发生，
   按语义只能作用于下一次布局；且本运行时为 New Architecture（文档称 LayoutAnimation 自动启用）——两点均待验证。

顺带确认：胶囊实时态带「（1s）」计时、回合结束变回「（N tok）」终态，§3.9「刻意不带已思考 Ns」兑现；
回合结束的其余行为（THINKING/停止/控制行撤除、标题定型、轮次计数）逐帧正常。

### 3.6 附带观察：回合结束锚定「短内容被钳制」——非回归

录屏终态消息不在视口第一行（上方露上一轮答案卡下缘）：「消息锚到第一行」的目标偏移超出 maxScroll，
被原生钳到真底——**整条消息+胶囊+答案全部可见、无折线切割**。11-02 已验证长答案锚定（shots-anchor/51），
本次为同一份锚定代码在设计内降级，**不是回归**（记录防误报）。

### 3.7 发送瞬间贴底 blip：自愈链确认

发消息瞬间仍用 `listRef.scrollToEnd`（`SessionScreen.tsx:1793`，滞后目标）+ running 翻转插入「发送方式」
控制行压缩视口 → atBottom 误判、「回到底部」胶囊悬挂。录屏确认 `followRef` 自愈链在大约 **+0.87s**

## 5. 方法沉淀（可复用）

- **快速动效采集**：`screenrecord` + `ffmpeg -fps_mode passthrough` 全帧抽取（ffmpeg 9.x 已移除 `-vsync`）；
  差分扫描脚本 `.scratch/diffscan.py`（glob + 阈值 + bbox，状态栏噪声已剔除）。
- **像素定位再点**：adb 单点不灵先怀疑坐标（今天发送钮目测差 73px）；PIL 深色像素 bbox 求圆心。
- **中文输入**：`adb shell input text '中文'` 会 NPE——设备侧中文只能手打，探针用英文。
- **MSYS 路径转换**：`adb pull/screenrecord` 的 `/sdcard/...` 需放进引号内整条 shell 命令或 `MSYS_NO_PATHCONV=1`。
- **快捷动线**：小上下文 = 快回合，造「实时动效」场景优先生新会话（聚焦页双击宠物建）。

### 8.3 F3 终局根因链（三层，全部定案——§3.5 的「仍是假设」已解）

1. **LayoutAnimation 在 Android 新架构默认死**（源码确认）：RN 0.88 `enableLayoutAnimationsOnAndroid=false`，
   Fabric 只有 flag 为真才把 `animationDriver_` 挂进 mounting 管线（`FabricUIManagerBinding.cpp:207-210/267-270/440-443`）；
   `setLayoutAnimationEnabledExperimental` 在 Bridgeless 下是死代码。替代：`RowFadeIn` Animated 淡入；
   `collapse.ts` 上膛保留（iOS 默认开启，那边走原生）。
2. 折叠可能落在**两个不同提交**（取决于 WS 批次）：同批（dsh-host 型）=换行一刀切；分提交（本机）=草稿行
   原地折叠一刀 + 换行一刀。判定：折叠侧=首个可见正文 delta（`foldFadeAtRef` 记时间戳），换行侧=240ms+160ms
   窗口内接着淡（`draftBodyPaintedRef` 记「正文画上过屏」）。
3. `landingRowIdRef` 若在 rows 变化的 effect 里清，会**早于虚拟化列表渲染新行**（logcat 实证：
   `rows-effect clear r51` 先于 `row-render r51` ref=null）→ 销账改由 `RowFadeIn` 淡入开始时的
   `onConsumed` 回调执行。

### 8.4 F2 二代缺陷（复验挖出）与修法

- 现象：发送后自己这条停在视口外——回显慢时（实测一轮 3.5s）只露气泡顶部 ~55px，「跟最新进展」意图的反面。
- 根因（真机帧级 + 源码）：待发行（+内容高度）与「发送方式」条（−视口高度）同一批上屏，
  `onContentSizeChange` 那一枪偶尔量到条挂载前的高度、落短一个条高；此后无事件重钉，直到回显。
- 修法（`efc6387`）：发送路径照键盘弹起口径补 60/280ms 两枪（`followRef` 门控），按真实高度落地
  （超出被原生钳到真底）。
- 复验：假网关 no-ack（永不回显）+ 溢出长列表，发送后逐帧完整可见（气泡 +「已发送，等确认…」）。
